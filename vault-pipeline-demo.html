The rule that holds it together: if an agent isn’t explicitly allowed a token, the vault refuses the request — the agent never even learns whether the underlying value exists.

DID / VC proxy re-encryption

The vault re-encrypts to the authorized agent’s key. Intermediaries move ciphertext — they never see plaintext. Step through it:

1

Worker presents a Verifiable Credential

DID-signed proof: “I am the holder of tok_name_7F3A” — no name attached.

2

Agent requests access for one job

Request names the token, the purpose, and the agent’s DID — nothing else.

3

Vault checks scope

Allowed? Proceed. Denied? Refuse and log the attempt. No partial access.

4

Vault re-encrypts

Ciphertext is transformed from the vault key to the agent’s public key. The vault is the only place plaintext exists, and only in memory.

5

Agent decrypts, acts, forgets

Agent uses the value for that one job, then discards it. Nothing is retained.

  • ✓

  • ✓

    Verifiable deletion

    When retention ends, deletion produces a signed receipt proving what was destroyed and when.

SAIF layered defenses

No single wall carries the whole load. Each layer assumes the one outside it can fail.

1 · Device layer

Nothing raw stored on the phone. Tokens only, memory-only capture, auto-discard.

2 · Token layer

Opaque, scoped, revocable tokens. A leaked token reveals nothing and can be killed instantly.

3 · Vault layer

Encryption at rest, keys isolated, proxy re-encryption so plaintext never transits intermediaries.

4 · Agent layer

Allowed / Denied scopes enforced by the vault, compartmentalized memory, no retention after a job.

5 · Audit layer

Every access, refusal, approval, and export is logged with tokens and timestamps — auditable without exposing PII.

6 · Deletion layer

Retention clocks run from day one. Expiry triggers verifiable deletion with a signed receipt.
